## Footer and status audit (#79)

On 2026-10-26 (PDT), a v0.2.8-based checkout on local macOS arm64/Go 1.27.3 audited every UI route for [#79](https://github.com/cliffom/bambu-tui/issues/79). ### Screen and state disposition

| Screen/state | Finding and resulting behavior or justified exception |
| --- | --- |
| Dashboard: Printers, Details, Notices | Keep one full-width slate row and one-column inset. Compact hints follow focus; historical events show delete rather than acknowledgement/dismissal. Empty filters offer reset. Feedback preserves help/quit and access to full status. Connection/freshness remain in the header/body. |
| Help | Replace inherited dashboard controls with scroll/page/close hints. The full keyboard reference scrolls at minimum size; dashboard quit stays captured. |
| Notice inspector: active, historical, resolved | Keep the full-screen footer. Advertise acknowledgement/dismissal only for active notices and deletion for historical events; retain return controls during errors. Browser failures persist with full URL/retry guidance in status. |
| Action needed: active/resolved, nested snooze | Keep navigation below the heading and acknowledgement/hide/snooze/close in the footer. Even a save failure at 60×18 preserves those actions. Printer state, independent observations, resolution text, and physical guidance remain in the body. |
| AMS/filament: populated/empty/unknown | Keep the bordered, inset dialog footer as a deliberate exception to full-width slate. No inventory means waiting guidance instead of slot/unit actions. Preserve unit/slot and scroll during status inspection and updates. |
| Notice decisions: empty/populated/reset | Render local-action feedback while the dialog remains open. Hide unavailable restore/unreview/reset hints; protect reset/cancel controls during failures. |
| Printer alerts, including suspended attention | Keep snooze/resume controls in the header and scroll/close below. Status can suspend both routes without clearing snoozes, selections, or the queued parent. |
| Notification activity: empty/populated, owner/observer/standby/paused | Keep outcome/reason/ownership in the body. Offer `r recheck` only for idle paused/standby workers; preserve current review/policy snapshots and consumed identities. Late export failures remain accessible here. |
| Config: General/Alerts/Printers | Keep selected-option help in the footer and storage/retry information in the body. Header controls follow editing/reset ownership. Ordinary saves remain silent. Overlapping failures expose a count and full status details. |
| Config: percentage input/reset/test pending/accepted/failed | Apply/reset/cancel instructions take precedence over retained test feedback. Status inspection keeps the test running and accepts its asynchronous result. Ordinary test success still dims at four seconds and expires at seven; failures remain available until another test. |
| Diagnostic export: preview/unavailable/writing/saved/failed | Keep scope, destination, and operation state in the scrollable body. Hints follow enabled export/retry/close actions. Late failures persist until a successful export; no upload occurs. |
| Clear-history and clear-notices confirmations | Keep explicit local scope and confirm/cancel controls. Both capture event IDs when opening and preserve later arrivals; clear-notices also retains independent occurrence checks. |
| Status / Feedback | New scrollable read-only view on `Ctrl+E` (`^E status` in hints). Shows complete source errors and recovery guidance plus recent feedback. Escape/Ctrl+E restores the same owner chain, confirmation, input, selection, and scroll. No disk history or notice decisions are created. |
| Shutdown: waiting/failure | No dedicated footer: compact exit/cancel instructions come first, followed by wrapped saving/failure text. Status does not take ownership during shutdown. |
| Below-minimum fallback/restoration | No footer: the resize instruction remains the only ordinary view. Hidden actions, confirmations, recovery, and status toggling stay blocked; Escape and dashboard quit retain their documented routing. Telemetry/results continue and restoration retains state. |
